# 证据索引

审核结论里引用依据时用这里的编号，例如 `[P-06]`、`[L-01]`。用户问「凭什么」时，能直接落到具体条款。

编号规则：`P` 平台《社区规范》（官方接口原文）｜`S` 专项规则与社区公约｜`L` 法律法规｜`N` 行业与平台技术要求。

## 来源类型（先看这一节）

| 类型 | 覆盖 | 获取方式 | 可靠性 |
|---|---|---|---|
| 官方原文（已抓取） | P-01 ~ P-13 | `scripts/fetch_official_rules.py` 从官方数据接口拉取，存为 `official-community-rules.md`，带内容哈希 | 高，可复现、可比对更新 |
| 法律条文 | L-01 ~ L-12 | 条目为国标条文要点；入口为官方数据库，按「核验」列的检索词可自行查原文 | 条文稳定，入口已实测可达 |
| 公开公告归纳 | S-01 ~ S-06 | 官方公告与权威转载整理，**非逐字原文** | 中，随公告更新 |
| 行业口径 | N-01 ~ N-04 | 平台公开要求与行业经验 | 参考值，不作硬性依据 |

**关于链接**：法规与公告页面多为前端渲染或带防爬，直链会随改版失效。这里给的是**官方站点 + 精确检索词**，比硬编码深链更耐用。

## 怎么核对一条依据

1. 打开「核验」列给的官方站点
2. 用给出的检索词搜法律/公告全名
3. 找到对应条款号，比对 `要点` 列
4. 条文序号或表述不一致时，以官方原文为准，回来修这张表

## 引用写法

结论里每条问题给一行依据，可多引用：

```
依据：[P-06] 导流到其他平台（原文明确含「二维码、水印」）＋ [S-01] 交易导流细则全场景适用
```

找不到对应编号时，写「无直接条款，按同类违规惯例判断」，并降为「建议」或「高风险」，不标「阻断」。
